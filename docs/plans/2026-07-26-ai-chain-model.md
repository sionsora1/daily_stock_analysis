# A 股 AI 产业链概率模型实施方案

## 目标与边界

在现有 Web 中新增一个独立的“AI 产业链模型”页面，为 A 股 AI 硬件、端侧与应用三个组别提供 10–30 个交易日的决策辅助：行业排序、个股上涨/相对跑赢概率、收益区间、回撤风险、买入/持有/减仓/回避建议和建议仓位。AI 硬件内单列“制造基础层”，覆盖半导体设备和材料，避免被服务器、光模块等直接算力需求标的掩盖；硬件池只覆盖直接供货的产业环节，不纳入数据中心运营、电网接入、变压器、发电等长周期基础设施。

第一版是可复现的量价、相对强弱和风险模型，不使用 LLM 生成交易结论，也不接券商、不自动交易。组合约束采用已确认的平衡配置：单股不超过 15%，AI 总仓不超过 60%，任一硬件子组不超过总资产 20%，观察池合计不超过总资产 15%，目标持有 6–8 只。

## 数据覆盖结论

| 数据项 | 项目现状 | 第一版处理 |
| --- | --- | --- |
| A 股三年日线 OHLCV、涨跌幅 | `DataFetcherManager.get_daily_data()` 已有多源 fallback；抽样可取得 2023-07-03 至 2026-07-24 的 733–743 个交易日 | 主数据。每行保存来源、覆盖率和缺失标记。 |
| 成交额 | Efinance 样本完整；Tencent fallback 样本 `amount` 全缺失 | 不能补 0。成交额因子只在可用时计算，缺失时退回成交量标准分，并降低数据质量等级。 |
| 技术指标、波动率、回撤、相对强弱 | 可由日线确定性计算；`StockDaily` 也已缓存部分均线 | 主因子，所有计算以当日收盘后已知数据为界。 |
| 指数与 AI 组别基准 | 项目可通过相同日线入口获取指数；没有可回溯的 AI 历史行业指数 | 用固定、带生效日期的 AI 分类池构建等权 AI 总基准和组别基准；同时展示宽基基准。 |
| AI 产业链股票池和组别归属 | 当前没有完整、可回放的 AI 分类资产 | 新建可审计的核心池/观察池分类表，包含硬件、端侧、应用、权重层级和生效区间。 |
| 估值、财务、资金流、龙虎榜 | `get_fundamental_context()` 当前为 partial；实测仅估值成功，成长、业绩、机构、资金流失败；且为当前快照而非历史时点序列 | 仅作为当前信息卡与风险提示，禁止进入第一版打分和历史回测。 |
| 新闻、事件、LLM 情绪 | 可选外部能力，但不满足本期“可复现结构化数据”要求 | 第一版不使用。 |

### 已确认的限制

1. 三年样本只能检验近期有效性，不能证明跨牛熊周期稳定有效。
2. 若分类池只按今天的成分回放历史，会带来幸存者/题材漂移偏差。回测报告必须明确标注；后续新增或移除股票要记录生效日期，不能改写历史。
3. 多源复权口径和成交额完整度不完全一致。模型必须展示数据来源和质量，覆盖不足时不发布新的组合建议。
4. 免费基本面数据不具备可靠的“当时可得”历史序列，因此第一版不称为基本面估值模型，而应准确称为“AI 产业链相对强弱与风险概率模型”。

## 模型设计

### 运行流程

```text
分类池（核心/观察 + 组别 + 生效日期）
  -> 批量补齐日线并记录来源/缺失
  -> 市场风险闸门
  -> 个股因子计算与组内相对排名
  -> 规则化评分、概率和区间校准
  -> 组合约束与建议仓位
  -> 持久化每日快照 / Web 展示 / 周度回测
```

### 因子与推荐逻辑

* 市场风险闸门先判断宽基和 AI 等权基准的趋势、波动率与回撤。闸门关闭时，不给出新增买入，现有建议降为持有、减仓或回避。
* 硬件大类按以下直接供货子组独立计算相对强弱、波动和组别集中度：EDA/IP、半导体材料、半导体设备及关键零部件、晶圆制造、AI 加速/CPU/存储及接口芯片、先进封装与测试、网络芯片与光互连、PCB/CCL/铜连接、AI 服务器/ODM/机柜、服务器电源、液冷与热管理。设备和材料属于 AI 需求的制造基础层，不能因题材弹性差异被服务器或光模块简单横向淘汰。数据中心运营、电网接入、变压器和发电因周期和驱动不同，明确排除在本期股票池外。
* 每个硬件子组维护版本化的慢变量档案：技术壁垒、供给紧缺度、扩产/验证周期、AI 需求传导强度和证据日期。慢变量只决定子组的基础权重、组内入选门槛和集中度上限；不得替代每日的价格、趋势、相对强弱、量能和回撤信号，也不得根据当天股价表现反向修改。
* 慢变量先依据已确认的产业链调研人工录入，按季度或出现可追溯的重大产业证据时复核；每次变动须保留旧版本、生效日期和证据说明。免费项目数据目前不能可靠地日度推导产业壁垒、真实紧缺度或资本开支传导，不能伪装成自动实时因子。
* 个股只使用当时可得的日线：5/20 日相对强弱、趋势结构、成交量（或可用时的成交额）变化、20 日波动率、回撤、流动性和异常涨跌停风险。
* 核心池正常参与排序；观察池降低评分权重并设置更高的入选门槛，且所有观察池持仓合计不得超过总资产 15%。
* 先在硬件、端侧、应用三个组内得到强弱，再在全 AI 池横向选择；总共选择 6–8 只，受单股 15%、AI 总仓 60%、任一硬件子组占总资产不超过 20% 的约束。
* 上涨概率、相对跑赢概率、预期收益和收益区间，来自历史上“相同分数/市场状态/持有期”的已实现结果分布，而非模型直接给出价格目标。输出 10、20、30 日三个口径，并以 20 日为默认展示。
* 数据覆盖率低于配置阈值、关键价格字段缺失、交易日未更新或流动性不足的股票只给出“数据不足/回避”，不可用静默默认值补齐。

## 实施任务

### 1. 定义可回放的分类池和模型配置

新增 `data/ai_chain_universe.json`，以版本化记录 AI 核心池与观察池的代码、名称、组别（hardware / edge / application）、硬件子组、层级、`effective_from`、`effective_to` 和人工核验来源说明。硬件子组覆盖 EDA/IP、材料、设备、晶圆制造、AI 芯片/存储、先进封测、网络/光互连、PCB/CCL/铜连接、服务器/ODM、服务器电源和液冷；禁止把数据中心运营、电网接入、变压器和发电写入该池。另新增 `data/ai_chain_industry_profiles.json`，以版本化记录每个子组的慢变量档案、证据日期和生效日期。新增 `src/schemas/ai_chain_model.py`，定义分类、慢变量档案、模型档案、数据质量、动作、因子快照、组合建议和回测结果的稳定枚举与数据结构。

先写 `tests/test_ai_chain_model_universe.py`：校验代码唯一、日期区间合法、组别/层级合法、核心与观察池不重叠、历史生效区间可查询。再实现分类资产加载和校验。

初始分类池需在开发开始时单独列出供确认；不能将临时概念股名单直接当成历史事实。若无法补齐历史成分变更，回测固定标注为“当前分类池的历史表现”，不作为无偏历史行业回测宣传。

### 2. 建立日线同步和数据质量层

新增 `src/services/ai_chain_market_data_service.py`，复用 `data_provider.base.DataFetcherManager` 和 `src/repositories/stock_repo.py`：优先读取本地 `StockDaily`，缺口才按单只股票补齐；同步 2023-07-01 至运行日的数据，并输出每只股票的日期覆盖、来源、`amount` 可用率、复权口径状态、最后交易日和失败原因。

新增 `tests/test_ai_chain_market_data_service.py`，用假日线数据覆盖：本地命中不联网、缺口回补、跨源成交额缺失、日期不连续、来源失败与覆盖率不足。实现时禁止在单元测试中访问真实数据源。

质量闸门按模型档案配置最小覆盖率；达不到时持久化失败原因，保留上一份成功结果但在 API/Web 明确标注“非最新”，不生成新交易建议。

### 3. 新建独立的模型持久化契约

在 `src/storage.py` 新增以下表，不复用当前面向 LLM 分析历史的 `BacktestResult` / `BacktestSummary`：

* `AiChainUniverseMember`：分类池的版本化成员和有效区间；
* `AiChainModelRun`：每次日度评分的日期、模型版本、市场闸门、数据覆盖与告警；
* `AiChainModelScore`：每只股票的因子、质量、概率、区间、风险、动作、排序与建议权重；
* `AiChainPortfolioBacktestRun`：回测参数、样本区间、成本模型、基准和汇总指标；
* `AiChainPortfolioBacktestPoint`：逐次调仓、持仓、交易成本、组合净值、基准净值与拒绝交易原因。

新增 `src/repositories/ai_chain_model_repo.py`，只暴露模型所需的事务化查询和写入接口。先写 `tests/test_ai_chain_model_repo.py`，覆盖幂等日度运行、同日版本覆盖规则、按日期取最新成功结果、回测明细分页和失败运行不污染成功快照；再实现模型和 repository。

### 4. 实现纯函数评分与组合构建引擎

新增 `src/core/ai_chain_model_engine.py`，让计算逻辑只接收时间排序的日线、分类池与模型档案并返回结构化结果，不在引擎内联网、读库或写库。

先写 `tests/test_ai_chain_model_engine.py`，覆盖：

* 以收盘日生成信号、以下一个可交易日开盘成交，防止未来数据泄漏；
* 慢变量档案在其生效日期之前不可见，且只影响子组基础权重与约束，不得覆盖个股快变量风险闸门；
* 观察池权重折减和更高入选门槛；
* 组内/全池排名、市场闸门关闭、单股 15%、AI 总仓 60%、任一硬件子组 20% 和观察池合计 15% 限制；
* 成交额缺失时的替代因子与质量降级；
* 缺失关键字段、停牌/极端波动、样本长度不足和所有候选被排除；
* 历史分桶概率与收益区间只使用评分日之前已完成的观察窗口。

再实现：市场风险闸门、特征计算、稳健标准化、分数、相同状态的历史分桶校准、组别分散化和建议动作。模型档案（持有期、权重、覆盖阈值、成本参数、仓位上限）必须版本化并随运行快照保存，不能靠后续代码变更解释旧结果。

### 5. 实现走步回测与压力测试

新增 `src/services/ai_chain_backtest_service.py`，按周度调仓运行从 2023-07-01 到可用最新日的走步回测：每次只使用当时之前完成的数据评分，次日开盘成交，持有 10/20/30 日口径并以 20 日为默认。日度评分用于观察，周度正常换仓；风险闸门触发可立即降风险。

先写 `tests/test_ai_chain_backtest_service.py`，覆盖无未来函数、下一开盘成交、成本扣减、不可交易买入跳过、市场闸门降仓、基准净值和回测可重跑一致性。再实现服务。

成本采用可配置的保守佣金、卖出税费和滑点，不把当前法规费率写死在逻辑中。报告至少输出年化收益、最大回撤、夏普/卡玛、换手、胜率、平均持有期、相对 AI 等权与宽基的超额、有效样本数、数据覆盖与未成交比例。

压力测试必须包含：成本/滑点上调、因子权重扰动、Top N 为 6 与 8、核心池与全池、不同周度调仓日和高波动阶段。若结论只在单一参数成立，页面必须显示“不稳健”，不能推荐实盘使用。

### 6. 接入 API 与异步任务

新增 `api/v1/endpoints/ai_chain_model.py` 并在 `api/v1/router.py` 注册 `/ai-chain-model`。模型服务维护独立的单工作线程手动任务队列，避免历史补数和回测阻塞 API 线程，也不影响现有日常任务调度。

接口契约：

* `POST /api/v1/ai-chain-model/runs`：提交日度同步与评分任务；
* `GET /api/v1/ai-chain-model/runs/{task_id}`：查询任务状态；
* `GET /api/v1/ai-chain-model/latest`：最新成功日度快照、市场闸门、分组排序和质量告警；
* `GET /api/v1/ai-chain-model/history`：历史日度结果；
* `POST /api/v1/ai-chain-model/backtests`、`GET /api/v1/ai-chain-model/backtests/{id}`：提交和读取回测；
* `GET /api/v1/ai-chain-model/data-coverage`：池内股票及基准的数据新鲜度和字段覆盖。

新增 `tests/test_ai_chain_model_api.py`，覆盖参数校验、任务排重、无成功快照的 404/空态、运行中状态、蛇形字段响应、过期数据警告和 API 鉴权继承。先写测试，再实现端点和 Pydantic 请求/响应模型。

第一版提供手动运行，不把任务悄悄并入现有日常 LLM 分析调度。完成运行稳定性验证后，再在 `src/services/runtime_scheduler.py` 增加一个独立、可配置、单飞的收盘后日度任务；若新增环境配置，必须同步 `.env.example` 和对应文档。

### 7. 新增独立 Web 页面

新增：

* `apps/dsa-web/src/api/aiChainModel.ts`；
* `apps/dsa-web/src/types/aiChainModel.ts`；
* `apps/dsa-web/src/pages/AiChainModelPage.tsx`；
* 对应页面/API 测试文件。

在 `apps/dsa-web/src/App.tsx` 注册 `/ai-chain-model`，在 `apps/dsa-web/src/components/layout/SidebarNav.tsx` 和 `ShellHeader.tsx` 增加入口与页面标题，在 `apps/dsa-web/src/i18n/uiText.ts` 补齐中英文文案。不要挤占现有 `/screening`：该页是可选 AlphaSift 外部选股能力，不能承载可回测的 AI 产业链模型。

页面从上到下展示：数据日期与覆盖告警、市场风险闸门、硬件（含半导体设备/材料制造基础层）/端侧/应用的强弱与资金建议、可筛选的个股概率表、建议组合与约束占用、收益区间和风险解释、回测与压力测试摘要、方法/局限说明。所有推荐旁固定展示“决策辅助，非自动交易或收益承诺”。

先写 Vitest 测试，覆盖空态、任务轮询、数据过期告警、三个组别、概率/区间格式、动作与仓位上限、回测不稳健提示和中英文本；再实现页面。完成后执行 `npm run lint`、`npm run test`、`npm run build`。页面最终验收需要截图，但截图只作为交付证据，不提交到仓库。

## 验证与验收顺序

1. 先运行新增的纯函数、repository、服务和 API 离线测试，再运行 `python -m py_compile` 覆盖改动 Python 文件。
2. 运行 `python -m pytest -m "not network"`；若环境允许，再运行 `./scripts/ci_gate.sh`。
3. 对少量 AI 样本执行一次人工日线同步，只核验来源、字段覆盖与数据日期，不以单次行情结果证明策略有效。
4. 运行完整三年走步回测及全部压力测试，检查无未来函数、成本已扣除、基准可复算、失败/缺失状态可见。
5. 运行 Web 的 lint、test、build，并用真实 API 快照验收空态、后台运行、数据过期和成功展示四条路径。

## 分期交付

* **MVP（建议先做）**：分类池、三年日线质量层、量价/相对强弱评分、日度快照 API、Web 排名页；无回测结论前不输出强操作建议。
* **第二期**：走步回测、成本模型、压力测试、建议组合与周度调仓展示。
* **第三期**：在有可追溯历史数据后，再评估引入点时点财务、资金流、事件和新闻结构化因子；每种新数据先单独做可得性与回测检验，不能直接叠加进现有分数。

## 回滚方案

功能全程使用独立路由、表和页面，不修改现有 LLM 回测、AlphaSift、持仓或日常分析链路。若出现数据质量或策略问题，禁用新导航入口/路由并停止独立任务即可；既有页面和数据库表不受影响，模型历史快照保留供审计。
