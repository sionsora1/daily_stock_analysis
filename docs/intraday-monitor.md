# 盘中综合信号监控

## 采样对齐

三分钟量价窗口会在锚点前后 90 秒内选择距离最近的可用样本。这样当整池行情抓取稍慢于轮询间隔时，正常报价不会被长期误判为“预热中”；超过容差的样本仍不会参与信号判断。

## 行情时效显示

数据源提供交易所时间戳时，页面显示该行情时效；未提供时，页面明确显示本地拉取时间及距当前的时长，不将本地时间误标为交易所行情时间。

盘中综合监控是独立于旧告警规则的可复用方案。后台服务按方案配置的间隔轮询实时行情，网页只负责展示和调整配置，因此关闭网页后仍会继续监控。

## 默认三层条件

- 事件标的：默认 `688825`（长鑫科技）。
- 板块 ETF：默认 `159516`（半导体材料设备主题 ETF）。
- 监控池：默认 19 只设备、零部件和材料标的，强势数量按 60% 计算，即至少 12 只；长鑫不计入 19 只分母。

每个标的需要高于当日开盘价，并且最近 3 分钟的价格与成交额结构表现为放量攻击、缩量回踩或稳定推进。系统按行情时间戳分别取最近 3 分钟和其前 3 分钟的累计成交额，不依赖固定样本数量；因此轮询间隔变化不会改变“3 分钟”的含义。比较两段窗口需要至少约 6 分钟的有效分时样本。

## 产业链代表性确认

默认长鑫方案会把监控池预先分为设备、关键零部件和材料三个产业方向，并给每个方向配置核心代表与备用代表。确认信号除原有三层条件外，还要求至少两个产业方向出现核心代表走强；这能避免某一个小环节集体冲高就被识别成完整的设备材料行情。

- 代表名单依据产业链位置预先配置，不会因为某只股票盘中领涨而临时替换。
- 备用代表只在该方向全部核心代表的行情不可用时才可显示为覆盖；核心代表本身走弱时，备用股走强不会替代核心结论。
- 所有核心和备用代码都必须属于监控池；监控池仍以完整分母计算，缺失或陈旧数据不会缩小分母。
- 通用方案可不配置代表组，此时保留原有三层条件，但不会增加产业链方向确认。

默认长鑫方案的名单如下；它们可在“方案设置 → 产业链代表组”中调整，变更后必须保存方案才会持久化：

| 方向 | 核心代表 | 备用代表 |
| --- | --- | --- |
| 设备 | `002371`、`603690` | `603283`、`603929`、`603163` |
| 关键零部件 | `688409`、`300260` | `688596` |
| 材料 | `603688`、`002409`、`600206` | `603650`、`688019`、`300054`、`300666`、`688126`、`688268`、`688106`、`605358` |

已有的默认长鑫方案无需重建：服务会在读取旧的 19 只监控池配置时自动应用上表的默认分组；首次保存后会把分组写入方案配置。自定义监控池若没有显式配置代表组，则不会启用这项额外确认。

系统不使用固定涨幅、量比或换手率阈值作为综合信号硬门槛；首日上市的事件标的不依赖前一交易日量比。

## 盘中状态

09:30—09:45 只观察，09:45—10:00 预热，10:00 后允许初步信号。进入 10:30 确认窗口后，系统重新从零统计连续有效刷新次数；只有确认窗口内连续两次满足三层条件才变为确认信号。确认后如长鑫跌破开盘价、ETF 转弱或监控池多数转弱，会记录信号失效。

数据缺失或陈旧行情只显示数据不足，不缩小监控池分母，也不直接生成失效信号。数据源显式标记为陈旧、或其行情时间戳超过 90 秒时不会计入有效信号；未提供提供方行情时间戳的数据会在页面标记为“时间戳未知”。

## API 与页面

- 页面：`/intraday-monitor`。
- API：`/api/v1/intraday-monitor/plans`、`/plans/{id}/history`、`/evaluate` 及启停/暂停/恢复接口。
- 页面“模拟测试”调用 `/plans/{id}/simulate`，注入确认、失效和恢复的确定性行情序列；模拟不会访问真实数据源，也不会写入真实方案状态。
- 状态变化历史保留 30 天；方案支持有效开始/结束日期，过期后自动不参与后台轮询。
- 后台按每个方案自身的轮询间隔判断是否到期；“立即评估”会强制刷新全部启用方案。
- 页面展示实际数据源、行情时间戳/新鲜度、字段缺失或陈旧原因、三层触发值、确认窗口进度、产业链代表覆盖和监控池逐标的状态；页面刷新频率随当前方案的轮询间隔变化。

创建新方案时只需填写事件标的、板块 ETF/指数和监控池代码；代码名称由实时数据源自动解析并显示。
